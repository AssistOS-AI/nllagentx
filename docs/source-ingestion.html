Source ingestion creates the stable textual substrate on which semantic authoring depends. It answers “what exact text was decoded, where is this passage, and has it changed?” It deliberately does not answer “what does this sentence mean for the task?” That second question belongs to LongTextJS authoring under an explicit coding-agent phase.

Why provenance begins before semantic code

A SourceSpan can support a finding only if the runtime can reproduce the text it names. Plain UTF-8 files make this look trivial, but even there a later edit can shift offsets or replace a selected phrase. PDFs complicate the problem further because visible text can be assembled from compressed streams, font mappings, and drawing operators rather than one contiguous byte range. Treating a byte offset or a string search as permanent evidence would make replay fragile.

nllAgent therefore defines decoded text as the coordinate space for semantic grounding. The source registry retains the original task-owned path, extractor identity and metadata, source digest, decoded-text digest, stable source units, and absolute decoded bounds. LongTextJS refers to that registry rather than opening arbitrary files. Anchor verification can then prove that a source ID, unit, interval, and selected-text hash still identify the passage the author intended.

Ingestion chooses an explicit decoder and fails visibly

The registry starts with the exact files declared by the task in stable lexical order. A task-owned module under source/extractors/ has first opportunity to decode its known format. Otherwise built-in UTF-8 decoding handles text, Markdown, CNL, CSV, and HTML. The dependency-free PDF extractor validates the document, rejects encryption, decodes supported streams, interprets ordinary text operands, and retains page metadata.

A decoder must return reproducible text or a typed failure. Empty extraction, encrypted PDFs, unsupported filters, scans without OCR, custom fonts that cannot be decoded, invalid extractor modules, and unsupported formats do not become successful blank sources. A task may add an OCR capture or specialized font map through an explicit extractor, making that extra authority reviewable and replayable instead of pretending Node.js built-ins inferred the missing glyphs.

Stable source units make large documents addressable

Validated decoded text is segmented deterministically into source units such as paragraphs, sections, pages, or another stable task-defined structure. The executable source/source-map.mjs records source and unit identities, paths, digests, extractor metadata, and decoded bounds. It is executable project data rather than JSON, but it remains non-semantic: a heading boundary says where text is, not whether the heading defines a legal exception.

Source units help a coding agent navigate a long document without copying the entire file into every semantic module. A LongText unit can anchor several claims inside one source unit and export semantic handles. The root module commits units in deterministic order and reconciles cross-unit identity. If one unit changes, dependency tracking can invalidate the affected materialization while preserving unchanged evidence.

The source tools expose evidence before Codex chooses its meaning

# Decode the retained source files and rebuild the executable source map before semantic authoring.
node nllAgent.mjs source ingest   --agent-dir examples/validation-agent   --task task-symbolic-validation

# Inspect source units and decoded bounds so the author can navigate the exact retained text.
node nllAgent.mjs source outline   --agent-dir examples/validation-agent   --task task-symbolic-validation

# Locate every exact occurrence of “alarm” and obtain candidate decoded spans for grounding.
node nllAgent.mjs source search   --agent-dir examples/validation-agent   --task task-symbolic-validation   --text "alarm"

# Recheck all committed LongTextJS anchors after ingestion or any source revision.
node nllAgent.mjs source verify-anchors   --agent-dir examples/validation-agent   --task task-symbolic-validation

source outline and source search are authoring aids. They reveal exact retained text and coordinates; they do not decide that an alarm event precedes a gate-opening event. A coding agent uses those observations together with the task instruction, ontology constructors, and LongText skill to decide which semantic terms and claims the passages support.

LongTextJS turns a passage into a grounded claim

In the validation example, the source says that the alarm sounded in Building A at 08:57 and that Ana opened the north gate at 09:00. Ingestion produces decoded text and one stable source unit. LongTextJS then creates two typed facility events, their actors, locations, and times, wraps them as source claims, and attaches each claim to its exact sentence. The facility-order circuit later queries those values and compares time, but ingestion never asserts that the order is valid.

This separation becomes more important with negation and policy. In the cold-chain source, a search can locate “no acknowledgement by Vale Laboratory.” LongTextJS must decide that the passage grounds a denied transfer acknowledgement by the receiving party, not a generic negative sentence and not merely absence of a positive event. The ontology supplies the roles; the task instruction supplies the purpose; the source span supplies evidence. No one of those inputs is sufficient by itself.

Anchor verification protects meaning from source drift

A committed anchor contains the source identity, decoded digest, unit, start and end bounds, and selected-text hash. Verification checks all of them. If a revision inserts text earlier in the file, the old numeric interval cannot silently select different words. The coding agent may realign the claim explicitly and rerun its tests, producing a new source snapshot and semantic identity. If it does not, ordinary execution reports a stale or invalid span.

Coverage is a separate semantic assertion. Processing every source unit may justify a LongText declaration that a particular concept was covered for a particular scope, but the source map itself cannot claim that all exceptions or all acknowledgements were materialized. This distinction prevents a completed decoding pass from becoming a false closed-world guarantee.

Exact input text remains distinct in the public answer

Findings carry semantic evidence values. Provenance traversal reaches verified SourceSpan handles, and the response renderer uses their selected substrings. Machine offsets remain in technical artifacts for replay, while response.md reproduces the exact passage. The evidence section is marked as copied input, and each source quotation has its own source marker and relative link. Generated conclusions and requirement explanations remain outside the blockquote.

This visual and semantic boundary prevents two opposite confusions. A reader does not have to resolve “characters 42–77” to understand the evidence, and a later formatter does not mistake generated explanation for text written in the source. If decisive evidence is missing from the finding, the renderer is not allowed to rediscover it with a keyword search; the semantic circuit or LongText grounding must be repaired where the missing meaning belongs.

A task-local extractor extends decoding without extending semantic authority

A specialized binary format can add source/extractors/bin.extractor.mjs. Its function receives immutable path, extension, bytes, and task-root information and returns text plus reproducible metadata. The registry validates and hashes that text exactly like built-in output. The extractor may understand bytes and glyphs specific to that format; it still must not create ontology terms, IntentJS, findings, or circuit code.

export function extractSource({ bytes }) {
  const text = decodeKnownCorpusFormat(bytes);
  return Object.freeze({
    text,
    metadata: Object.freeze({ format: "known-corpus-v1" })
  });
}

The result is a clean chain of authority: the extractor establishes decoded evidence, the coding agent authors a semantic interpretation, the transaction validates that interpretation, circuits derive results, and response composition quotes only verified passages. Each step can be inspected and repaired without asking another layer to guess what the previous one omitted.
