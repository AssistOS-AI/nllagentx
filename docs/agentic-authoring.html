Agentic authoring is the model-dependent half of nllAgent. It exists because an instruction and document do not arrive with their intended entities, scopes, rules, evidence relations, or completeness assumptions already marked. Codex resolves those choices by writing inspectable programs under explicit ownership. The runtime then validates and executes the programs independently.

Authoring begins by deciding what should survive this task

The first architectural decision is ownership. Suppose a brief asks for an operational-policy reviewer that can detect contradictory rules, missing exception justifications, unsupported conclusions, and requests for generated procedures. Those concepts and behaviors are useful across many documents. They belong to the agent: the ontology can define operational rules, invocations, justifications, support relations, and procedure requests; reusable circuits can analyze those meanings without knowing the text of any future case.

A concrete task then says “check this exception” and supplies a policy plus an invocation record. The exact invocation, its quoted policy, its missing justification, and the task's desired evidence-led answer belong only to that task. IntentJS records the requested review. LongTextJS creates the source-grounded rule, invocation, and denied or absent justification. If these facts were written into the reusable agent ontology, a later document could inherit them as default knowledge. If the reusable exception algorithm were copied into every task, review and calibration would fragment. Agentic authoring separates those two mistakes before code is written.

An agent brief teaches vocabulary and behavior, not source facts

Agent-level phases start from a retained natural-language brief. The architecture phase decides which meanings, capabilities, profiles, response policies, and tests form one coherent agent. The ontology phase gives stable identities and typed constructors to the reusable meanings. The circuit phase writes checks and generation procedures against patterns over those meanings. A response phase may add audience-specific grouping or controlled vocabulary when framework defaults are insufficient. Tests define microcases that must continue to hold across tasks.

The resulting agent folder is a persistent semantic package. Its code is expected to survive sources that use different names and sentence structures because circuits operate over semantic handles rather than strings. A contradiction circuit compares grounded action, condition, scope, and effect. An exception circuit asks whether an invocation is governed by a policy and connected to a grounded justification record. Their lexical manifestations are handled during LongText authoring; their decision semantics remain reusable.

A task instruction chooses an operation; the source supplies its evidence

Task-level authoring keeps the instruction separate from the document. Codex reads the instruction to create IntentJS: analysis or generation mode, concerns, target scope, evidence discipline, requested outputs, assurance, and presentation directives. It reads decoded source text to create LongTextJS: mentions, entities, events, claims, voices, modalities, polarities, contexts, alternatives, quantities, times, identities, and coverage. The original instruction and source remain retained alongside those programs, so a reviewer can compare the interpretation with what was actually asked and written.

LongText authoring is not a transcription exercise. “The operator may bypass inspection during an emergency, provided the invocation records a justification” contains a permission, an exception condition, and a required justification relation. “No justification was recorded” is an explicit denial, not merely failure to see a positive sentence. A later circuit can reach a violation for the right reason only if those distinctions were materialized and grounded at exact spans.

Task-local ontology or circuits are exceptional but legitimate. A cold-chain source can introduce calibration-at-transfer, excursion quarantine, and stability-study support that a core-only agent cannot express. Adaptive authoring adds those meanings and the release-support circuit under the task. The code is not automatically promoted after one success; promotion requires a separate reusable contract and calibration across independent cases.

nllAgent prepares an evidence-rich coding workspace

The framework does not paste the repository into one enormous prompt. It resolves the selected phase's skill dependency graph and materializes exactly the context artifacts declared by that closure. An ontology phase needs the SDK and resolved ontology catalogs. A circuit phase also needs circuit and response catalogs, diagnostics, and runtime contracts. A task grounding phase needs the source outline, exact decoded source, active ontology, profile resolution, and intent. Every catalog is generated from live project objects and points back to canonical modules; none replaces the code it describes.

The run directory receives dependency-ordered skills, exact DS contracts, context artifacts, INSTRUCTIONS.md, and an executable run manifest. The instructions name the canonical working directory and edit owner. Codex reads the contracts and catalogs, opens deeper source as needed, and edits the agent or task directly. The run directory retains context and logs; it is not a staging copy from which nllAgent later reconstructs semantic files.

Skills divide one coding lifecycle into bounded responsibilities

Each project skill pairs human operational instructions in SKILL.md with an executable workflow.mjs. The workflow declares specifications, context artifacts, CLI tools, dependencies, edit roots, and applicable phases. Dependencies establish the reading and installation order: a circuit author receives runtime and ontology contracts before circuit-specific instructions, while a LongText author receives intent and ontology context before grounding the source.

The separation is about responsibility, not artificial isolation. The architect may identify that an ontology and four circuits are needed. The ontology author may expose constructors used by the circuit author. The task intent author may select a capability supplied by those circuits. The LongText author may discover a missing role and route a typed refinement back to ontology work. Each phase sees enough shared semantic context to make those handoffs explicit, while edit roots prevent a task grounding phase from silently redesigning framework primitives.

The coding-agent chapter examines what Codex sees and does across these phases. How coding skills work then exposes the live manifest values and verification workflow of every individual skill.

Completion of a Codex process is only the start of acceptance

The adapter records that Codex started, which directory it used, which instructions it received, what it printed, which files changed, when it finished, and its exit status. That proves an authoring process occurred. It does not prove that a role range is correct, a source anchor still matches, a decision table covers unknown and conflict, or the public response quotes decisive evidence.

Phase-specific checks therefore inspect the authored artifact. Ontology modules must import, seal, and preserve identity closure. Intent must retain the instruction and request actual capabilities and output policy. LongText must commit and verify every source anchor. Circuits must declare dependencies, emit evidence-bearing results, and pass focused microcases. Response behavior must preserve selected findings while excluding internal projections. Tests execute without Codex, so a second process judges artifacts rather than trusting the author's report.

Real evaluation proves authoring rather than fixture replay

A committed example can prove runtime behavior, but it cannot prove that a coding agent created the semantics from natural language. The agentic evaluation begins with an isolated folder that lacks the target reusable programs. It retains the exact brief, invokes Codex for the agent phases, creates random-ID tasks, invokes Codex for task intent and grounding, and records the created code and every phase run. Each case must then pass semantic expectations and reproduce its result under ordinary model-free replay.

The four rule-review cases deliberately demand different behaviors: a real contradiction, a missing justification, an unsupported conclusion, and controlled procedure generation. Strict oracles reject unexpected material findings as well as missing expected ones. Exact decisive quotations are part of acceptance, so a correct label with weak evidence is not enough. Failed attempts remain retained; a later repair is another explicit run, not a rewritten history.

Adaptive authoring extends the same contract inside one difficult task

Ordinary tasks should reuse a reviewed agent. When inherited ontology or circuits cannot express the requested operation, analyze --author-adaptive makes the exception explicit. Codex audits intent, ontology, grounding, circuit capability, response policy, and tests under task ownership. The planner composes inherited and local providers. Deterministic acceptance requires concrete material output, valid anchors, focused tests, qualitative CNL, requested abstract and symbolic evidence, and equivalent replay. A mandatory review examines even an initially successful run for overfitting, missing unknown behavior, weak provenance, or empty assurance.

Once accepted, the task can run again without Codex. This is the architectural endpoint of authoring: the flexible model has left behind code precise enough that the system can explain, test, and repeat what it now means by the original request.
